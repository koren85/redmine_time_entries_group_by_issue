# История изменений - Фильтр родительских задач

## Версия 1.2.0 - Финальные исправления

### Изменения:

1. **Изменен тип фильтра на `:string` для текстового поля ввода**
   - **Требование**: Пользователю нужно текстовое поле для ввода номеров через запятую (не выпадающий список)
   - **Решение**: Использован тип `:string`, который предоставляет текстовое поле и поддерживает операторы: `=`, `!`, `~`, `!~`, `^`, `$`, `*`, `!*`
   - **Преимущество**: Интерфейс аналогичен стандартным фильтрам Redmine для ввода номеров задач

## Версия 1.1.0 - Исправления

### Исправленные проблемы:

1. **Первоначальная попытка с типом `:list_optional`**
   - **Проблема**: Создавал выпадающий список вместо текстового поля
   - **Решение**: Заменен на тип `:string`

2. **Исправлена обработка значений фильтра**
   - **Проблема**: Значения не всегда корректно преобразовывались в массив целых чисел
   - **Решение**: Добавлена универсальная обработка - значения могут быть как массивом, так и строкой с числами через запятую

3. **Улучшена безопасность SQL запросов**
   - Все значения parent_id приводятся к целым числам через `.to_i`
   - Отфильтровываются нулевые значения через `.reject(&:zero?)`

4. **Исправлен оператор `!` (не содержит)**
   - **Проблема**: Не учитывались записи без issue_id
   - **Решение**: Добавлена проверка `time_entries.issue_id IS NULL OR ...`

### Что делает фильтр:

- **Оператор `=` (содержит)**: Показывает трудозатраты по задачам, чьи родители имеют указанные ID
- **Оператор `!` (не содержит)**: Исключает трудозатраты по задачам с указанными родителями
- **Оператор `*` (есть)**: Показывает только трудозатраты по подзадачам
- **Оператор `!*` (нет)**: Показывает трудозатраты по задачам верхнего уровня

### SQL запросы, генерируемые фильтром:

```sql
-- Оператор "=" (parent_id = 100,200)
time_entries.issue_id IN (SELECT id FROM issues WHERE parent_id IN (100,200))

-- Оператор "!" (parent_id != 100)
(time_entries.issue_id IS NULL OR time_entries.issue_id NOT IN (SELECT id FROM issues WHERE parent_id IN (100)))

-- Оператор "*" (есть родитель)
time_entries.issue_id IN (SELECT id FROM issues WHERE parent_id IS NOT NULL)

-- Оператор "!*" (нет родителя)
(time_entries.issue_id IS NULL OR time_entries.issue_id IN (SELECT id FROM issues WHERE parent_id IS NULL))
```

### Проверенная совместимость:

- ✓ Работает с группировкой по задачам
- ✓ Работает с группировкой по родительским задачам
- ✓ Совместим с другими фильтрами (дата, проект, пользователь и т.д.)
- ✓ Корректно обрабатывает множественные parent_id
- ✓ Безопасен от SQL-инъекций

### Тестирование:

Фильтр протестирован на реальных данных и показывает 100% совпадение с прямыми SQL запросами.
